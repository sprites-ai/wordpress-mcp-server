# WordPress MCP Server

The Sprites MCP server connects your WordPress site to any MCP client. Ask for a post and Sprites researches the keyword, writes it in your site’s voice, sets the metadata and internal links, and creates it as a draft in WordPress — publishing stays a separate approval you give.

## Quick start

1. **Connect WordPress in Sprites.** Sign up at [sprites.ai](https://www.sprites.ai) and connect WordPress once in the Sprites integrations menu. Start a trial from the Sprites site.
2. **Add the server to your client** with the URL `https://mcp.sprites.ai/mcp` (one endpoint for every client and every channel).
3. **Sign in.** Your client opens the Sprites consent screen. Sign in with the account your channels are connected to and approve.
4. **Ask.** Try: "With Sprites, write a post on "wordpress speed optimization" and draft it in WordPress."

## Setup by client

### Claude (claude.ai and Claude Desktop)

Works on Free (one custom connector), Pro, Max, Team and Enterprise.

1. Settings, then Customize, then Connectors. On Team and Enterprise an Owner adds it once under Organization settings, Connectors.
2. Click **+**, then **Add custom connector**. Name it `Sprites` and paste `https://mcp.sprites.ai/mcp`. Leave Advanced settings empty.
3. Click **Connect**, sign in to Sprites and approve.

Claude draws the Sprites approval card in the chat, so you can edit a budget or a headline in place and approve it.

### Claude Code

```bash
claude mcp add --transport http sprites https://mcp.sprites.ai/mcp
```

Then type `/mcp` inside Claude Code to finish the browser sign-in.

### ChatGPT

Plus, Pro, Business, Enterprise and Edu, on the web app. Not available on Free.

1. Settings, Security and login: turn on **Developer mode**. On Business and Enterprise an admin has to allow it first.
2. Settings, **Plugins** (formerly Connectors), then **+** to create an app.
3. Name `Sprites`, MCP server URL `https://mcp.sprites.ai/mcp`, Authentication **OAuth**. Tick the trust box and click Create.
4. Connect the app and sign in to Sprites.

### Cursor

`~/.cursor/mcp.json` (every project) or `.cursor/mcp.json` (one repo):

```json
{
  "mcpServers": {
    "sprites": {
      "url": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Cursor discovers the Sprites authorization server from the endpoint and opens a browser to sign in.

### Codex

```bash
codex mcp add sprites --url https://mcp.sprites.ai/mcp
codex mcp login sprites
```

Or by hand in `~/.codex/config.toml`:

```toml
[mcp_servers.sprites]
url = "https://mcp.sprites.ai/mcp"
auth = "oauth"
```

### VS Code and GitHub Copilot

`.vscode/mcp.json`. The top-level key is `servers`, not `mcpServers`, and a remote server needs `"type": "http"`:

```json
{
  "servers": {
    "sprites": {
      "type": "http",
      "url": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Run **Auth** above the entry, sign in, then switch Copilot Chat to **Agent** mode. Ask mode does not call MCP tools.

### Gemini CLI

`~/.gemini/settings.json`. Use `httpUrl`; a `url` entry is treated as SSE:

```json
{
  "mcpServers": {
    "sprites": {
      "httpUrl": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Restart the CLI; the first call opens the sign-in. Check with `gemini mcp list`.

## What it can read

- Your published posts, pages, categories and internal link structure
- Search Console queries, impressions, clicks and average position
- Keyword volume, difficulty and what currently ranks
- Existing titles, meta descriptions and schema

## What it can change (with your approval)

- Posts and pages, created as drafts
- Titles, meta descriptions, focus keyphrases, headings and FAQ schema
- Edits to existing pages, delivered as a reviewable diff
- Publishing is a separate, explicit approval — never implied by a draft

Every change arrives as an approval with the before and after. In Claude and ChatGPT it is a card you can edit
in place. In clients without cards, Sprites returns the change written out with a gate id, and applies it only
after you confirm (`approve_change`). Nothing is applied by the model on its own.

## Permissions

- **Application Password.** A per-user password generated under Users, Profile, used for REST API calls instead of your login password.
- **User role.** The REST API applies your WordPress role, so publishing needs Author, Editor or Administrator.
- **WordPress.com OAuth.** Sites hosted on WordPress.com sign in with WordPress.com instead.
- **What Sprites asks for.** An Application Password or the Sprites plugin on a self-hosted site, or WordPress.com sign-in on a hosted one.
- **What you skip.** The credential stays in Sprites rather than in a config file beside your agent, and your agent signs in to Sprites with OAuth.
- **Your AI client never holds a platform credential.** It holds a Sprites OAuth token bound to `https://mcp.sprites.ai/mcp`.

## Tools

The server exposes 20 tools to the model: 6 read tools and 14 write tools. Write tools that touch an ad account or a site only propose; nothing reaches either until you approve it. The tools that do the WordPress work:

| Tool | What it does on WordPress |
|---|---|
| `write_seo_blog_post` | A researched post created as a WordPress draft, with metadata and internal links set. |
| `create_seo_page` | A landing or service page created or edited, delivered as a diff. |
| `create_aeo_content` | FAQ and comparison content written to be quoted by ChatGPT and AI Overviews. |
| `research` | Keyword volume, difficulty and what already ranks for the target. |
| `analyze` | Search Console impressions, clicks and the pages that moved. |
| `schedule_task` | A recurring content brief or refresh that runs on its own. |

WordPress requests use `channel: seo_web`. Name another channel, or `all`, to compare.

Every task tool takes the same input: `goal` (the request written to stand on its own: Sprites sees only this
string, not the chat), `title` (a short label), `channel`, and `today` (the user's local date, so "last 30 days"
resolves correctly). Long tasks return a run id; `task_status` collects the result and `cancel_task` stops it.

## FAQ

**Is this a server I have to host?**
No. It is a hosted remote MCP server. Paste `https://mcp.sprites.ai/mcp` into your client and sign in.

**How does it compare with other WordPress MCP servers?**
There are two. WordPress.com hosts its own MCP server, with posts, pages, comments, categories, tags and media each switched on separately and every change confirmed in the chat. Self-hosted sites use the official WordPress/mcp-adapter plugin, which exposes the Abilities API in WordPress 6.9 as MCP tools. Both official routes are open source, and so is Automattic’s mcp-wordpress-remote, which bridges a client to a site running the adapter. They give an agent hands on WordPress; what to write is left to the model and your prompt. Sprites reads Search Console and keyword data before it writes, works on self-hosted sites over an application password or the Sprites plugin, and holds every post and page edit as a draft or a diff, with going live a separate approval.

**Is there an official WordPress MCP server?**
Two, one for each kind of WordPress. WordPress.com hosts an MCP server with write tools for posts, pages, comments, media and taxonomies, each change confirmed by you. Self-hosted sites use the official WordPress/mcp-adapter plugin, which exposes the Abilities API from WordPress 6.9 as MCP tools. Automattic’s earlier wordpress-mcp repository has been archived, so any guide telling you to install that one is out of date.

**What is the difference between that and Sprites?**
The adapter exposes WordPress to a model. It does not do the research, know what already ranks, read Search Console, or write in your voice — it gives an agent the ability to create a post, and leaves the deciding to whatever is on the other end. Sprites is the other end.

**Do I need to install a plugin?**
Not necessarily. Sprites connects over the WordPress REST API with an Application Password, which is native to WordPress and takes a minute to create. The plugin is there for sites that lock the REST API down.

**Will it publish to my live site without asking?**
No. Posts and pages are created as drafts. Publishing is a separate approval, and an edit to a page that is already live arrives as a diff you read before anything changes.

**Does it work with WooCommerce, Yoast or Rank Math?**
Yes. Metadata is written through the fields your SEO plugin already uses, so a post arrives with its focus keyphrase and description populated rather than flagged red in the editor.

**Which agents can I use it from?**
Claude, ChatGPT, Codex, Cursor, Gemini, Grok and every other client that speaks remote MCP. One endpoint, one sign-in, no per-client configuration.

**Does it cover other channels?**
Yes. The same URL reaches Google Ads, Meta Ads, LinkedIn Ads, TikTok Ads, Reddit Ads, Microsoft Advertising,
Apple Ads, GA4, Search Console, Shopify, SEO and AI visibility, and Google Business Profile, for whatever is
connected in Sprites. See [ads-mcp-servers](https://github.com/sprites-ai/ads-mcp-servers).

**How much does it cost?**
The connector is included in every Sprites plan, and every plan starts with a short trial. See sprites.ai for current plans. WordPress is billed by its own vendor as usual.

**The client says it has no tools, or every call is unauthorized.**
Remove the server, re-add it with exactly `https://mcp.sprites.ai/mcp`, and sign in again. Grants are bound to that one URL.

**How do I revoke access?**
Disconnect the connector in your client, or remove the connection in Sprites. The next tool call fails closed.
